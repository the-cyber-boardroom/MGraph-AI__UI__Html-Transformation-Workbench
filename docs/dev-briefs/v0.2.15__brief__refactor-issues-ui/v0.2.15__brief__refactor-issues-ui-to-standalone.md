## Overview

This is an **IFD Major Version Refactor**. The goal is to extract the issues tracking UI components from the HTML Transformation Workbench (`v0/v0.1/v0.1.x`) and consolidate them into a new standalone application at:

```
mgraph_ai_ui_html_transformation_workbench__ui/issues_ui/
```

The new `issues_ui` application will follow the IFD (Iterative Flow Development) methodology with its own versioning, starting fresh with `v0.1.0` that contains all consolidated issue tracking code.

---

## IFD Methodology Explained

### What is IFD (Iterative Flow Development)?

IFD is a versioning methodology where:

1. **v0.1.0 is the base** - Contains all foundational code
2. **v0.1.x versions are surgical overrides** - Each version ONLY contains files that change from the previous version
3. **Later versions load earlier versions first** - Scripts are loaded in order: v0.1.0, then v0.1.1, then v0.1.2, etc.
4. **Override by redefinition** - Later files override earlier ones by redefining classes/functions

### IFD Major Refactor

A **major refactor** consolidates all those surgical overrides back into a single `v0.1.0`, creating a clean baseline. This:

1. **Consolidates** all scattered overrides into one cohesive codebase
2. **Simplifies** the include chain (no more `../v0.1.0/` references)
3. **Resets** the version counter for the new application
4. **Enables** independent versioning from the parent application

### Why This Refactor?

The issue tracking code is currently spread across v0.1.0 through v0.1.7 with:
- Base services in v0.1.0
- Issue-specific services in v0.1.6
- Graph API services in v0.1.7
- Multiple shell overrides
- Various component additions

Consolidating into a standalone `issues_ui/v0/v0.1/v0.1.0` gives us a clean slate while preserving all functionality.

## REST API Endpoints (From openapi.json)

### CRITICAL: Correct API Path Mappings

The current v0.1.7 `graph-service.js` uses incorrect paths. Here are the CORRECT paths:

#### Issues API (Legacy Format)
```
Base: /issues/api

GET    /issues/api/issues                    # List all issues
POST   /issues/api/issues                    # Create issue
GET    /issues/api/issues/{issue_id}         # Get issue
PATCH  /issues/api/issues/{issue_id}         # Update issue
DELETE /issues/api/issues/{issue_id}         # Delete issue
POST   /issues/api/issues/{issue_id}/comments # Add comment
PATCH  /issues/api/issues/{issue_id}/status  # Update status (query: status=)
```

#### Nodes API (Graph Format)
```
Base: /nodes/api

GET    /nodes/api/nodes                      # List all nodes
POST   /nodes/api/nodes                      # Create node
GET    /nodes/api/nodes/type/{node_type}     # List nodes by type
GET    /nodes/api/nodes/{label}              # Get node by label
PATCH  /nodes/api/nodes/{label}              # Update node
DELETE /nodes/api/nodes/{label}              # Delete node
```

#### Links API
```
Base: /links/api

GET    /links/api/nodes/{label}/links                  # List links for node
POST   /links/api/nodes/{label}/links                  # Create link
DELETE /links/api/nodes/{label}/links/{target_label}   # Delete link
```

#### Labels API
```
Base: /labels/api

GET    /labels/api/labels                    # List labels
POST   /labels/api/labels                    # Create label
DELETE /labels/api/labels/{name}             # Delete label
```

#### Types API
```
Base: /types/api

GET    /types/api/types/{name}               # Get node type
DELETE /types/api/types/{name}               # Delete node type
GET    /types/api/link-types/{verb}          # Get link type
```

#### Server API
```
Base: /server

GET    /server/status                        # Server status
GET    /server/api                           # API info
GET    /server/storage                       # Storage status
GET    /server/git                           # Git status
GET    /server/types                         # Types info
GET    /server/index                         # Index info
```
