### Bug-7: Modal Data Lost on Outside Click

#### Current Problem

When creating a new issue, if the user accidentally clicks outside the modal overlay, the modal closes and all entered data (title, description, tags) is lost without warning.

#### User Flow (Current - Buggy)

```
┌─────────────────────────────────────────────────────────────────┐
│  User Flow: Creating an Issue (Current Bug)                     │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  1. User clicks "+ New"                                         │
│     ┌──────────────────────────────────────────────────┐        │
│     │  Create New Task                            [X]  │        │
│     │  ─────────────────────────────────────────────── │        │
│     │  Title: "Add user authentication"                │        │
│     │  Description: "We need OAuth2 support for..."    │        │
│     │  Tags: "security, auth, priority"                │        │
│     │                                                  │        │
│     │  [Cancel]                     [Create Task]      │        │
│     └──────────────────────────────────────────────────┘        │
│                              │                                  │
│                              │ User accidentally clicks         │
│                              │ outside modal (dark overlay)     │
│                              ▼                                  │
│  2. Modal closes immediately - ALL DATA LOST!                   │
│     User frustrated, has to re-enter everything                 │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Proposed Solution

Two options:

**Option A: Disable click-outside-to-close (Recommended)**
- Only allow closing via Cancel button or X button
- Most straightforward, prevents accidental data loss

**Option B: Confirm before closing if form has data**
```javascript
handleOverlayClick(e) {
    if (e.target.id === 'cnm-overlay') {
        if (this.hasUnsavedData()) {
            if (confirm('Discard unsaved changes?')) {
                this.close();
            }
        } else {
            this.close();
        }
    }
}
```

#### Implementation Plan

1. Modify `create-node-modal.js` overlay click handler
2. Check if form has data before closing
3. Either disable overlay click or show confirmation

#### Files to Modify

- `v0.1.5/components/create-node-modal/create-node-modal.js`

### Bug-8: Back to Kanban Navigation

#### Current Problem

When navigating from Kanban → Node Detail (by clicking a card), clicking "Back" goes to the Issues list instead of back to Kanban, breaking the user's mental model.

#### User Flow Diagram

```
┌─────────────────────────────────────────────────────────────────┐
│  Navigation Flow: Current (Broken)                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐     click card     ┌─────────────┐             │
│  │   KANBAN    │ ─────────────────▶ │ NODE DETAIL │             │
│  │   BOARD     │                    │   (Bug-5)   │             │
│  └─────────────┘                    └──────┬──────┘             │
│                                            │                    │
│                                            │ click "Back"       │
│                                            ▼                    │
│                                     ┌─────────────┐             │
│                                     │ ISSUES LIST │  ← WRONG!   │
│                                     │  (not Kanban)│             │
│                                     └─────────────┘             │
│                                                                 │
├─────────────────────────────────────────────────────────────────┤
│  Navigation Flow: Fixed                                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐     click card     ┌─────────────┐             │
│  │   KANBAN    │ ─────────────────▶ │ NODE DETAIL │             │
│  │   BOARD     │                    │   (Bug-5)   │             │
│  └─────────────┘                    └──────┬──────┘             │
│        ▲                                   │                    │
│        │                                   │ click "Back"       │
│        └───────────────────────────────────┘  ← CORRECT!        │
│            Return to previous view (Kanban)                     │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Implementation Plan

1. Track navigation history in shell or use browser history
2. Modify "Back" button in node-detail to use `history.back()` or tracked previous app
3. Alternative: Store `previousAppId` in state when navigating

#### Technical Approach

```javascript
// Option 1: Use browser history
document.querySelector('#nd-back').addEventListener('click', () => {
    history.back();  // Let browser handle it via hash routing
});

// Option 2: Track in shell state
navigate(targetAppId) {
    this._previousAppId = this._currentAppId;  // Store before changing
    // ... rest of navigation
}

// In node-detail back handler:
goBack() {
    const previousApp = window.issuesApp.router.previousApp || 'node-list';
    window.issuesApp.router.navigate(previousApp);
}
```

#### Files to Modify

- `v0.1.5/components/shell/issues-shell.js` (track previous app)
- `v0.1.5/components/node-detail/node-detail.js` (use previous app in back button)

│  Delete Task-18? This cannot be undone.│

#### Proposed Solution

Use the messages panel for inline confirmations:

```
┌─────────────────────────────────────────────────────────────────┐
│  Messages Panel - With Confirmation                             │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────────────────────────────────────────────────┐    │
│  │  ⚠️ CONFIRM DELETE                                      │    │
│  │  ───────────────────────────────────────────────────────│    │
│  │  Delete Task-18? This cannot be undone.                 │    │
│  │                                                         │    │
│  │                          [Cancel]  [Delete]             │    │
│  └─────────────────────────────────────────────────────────┘    │
│                                                                 │
│  ● Error: Failed to load...                               [x]   │
│  ○ Graph loaded: 20 nodes                                       │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### API Design

```javascript
// messages-service.js - Add confirm method
messages.confirm(text, options) {
    // Returns a Promise that resolves to true/false
    return new Promise((resolve) => {
        const id = this.add('confirm', text, {
            confirmLabel: options.confirmLabel || 'Confirm',
            cancelLabel: options.cancelLabel || 'Cancel',
            confirmStyle: options.confirmStyle || 'primary',  // 'primary', 'danger'
            onConfirm: () => { this.dismiss(id); resolve(true); },
            onCancel: () => { this.dismiss(id); resolve(false); }
        });
    });
}

// Usage in node-detail.js
async handleDelete() {
    const confirmed = await window.issuesApp.messages.confirm(
        `Delete ${this.state.node.label}? This cannot be undone.`,
        { confirmLabel: 'Delete', confirmStyle: 'danger' }
    );
    if (confirmed) {
        await this.deleteNode();
    }
}
```

#### Implementation Plan

1. Add `confirm` message type to `messages-service.js`
2. Update `messages-panel.js` to render confirmation messages with buttons
3. Auto-expand panel when confirmation is shown
4. Replace `confirm()` calls in node-detail delete handler
5. Add appropriate styling for confirm/cancel buttons

#### Files to Modify

- `v0.1.5/js/messages-service.js`
- `v0.1.5/components/messages-panel/messages-panel.js`

### Task-25: Open Issue in New Tab from Kanban

#### Current Problem

Users cannot open an issue in a new browser tab from the Kanban board. They have to:
1. Click to navigate
2. Copy URL
3. Open new tab
4. Paste URL

#### Proposed Solution

1. Make cards work with browser's native "Open in New Tab" (Cmd/Ctrl+Click, right-click)
2. Use proper anchor links with hash URLs

#### Technical Approach

```
┌─────────────────────────────────────────────────────────────────┐
│  Implementation Options                                         │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  Option 1: Wrap card in <a> tag                                 │
│  ─────────────────────────────────────────────────────────────  │
│  <a href="#/issue/Task-18" class="kb-card-link">                │
│    <div class="kb-card">...</div>                               │
│  </a>                                                           │
│                                                                 │
│  Pros: Native browser behavior works automatically              │
│  Cons: May affect drag-and-drop                                 │
│                                                                 │
│  Option 2: Handle Cmd/Ctrl+Click programmatically               │
│  ─────────────────────────────────────────────────────────────  │
│  card.addEventListener('click', (e) => {                        │
│    if (e.metaKey || e.ctrlKey) {                                │
│      window.open(`#/issue/${label}`, '_blank');                 │
│    } else {                                                     │
│      // Normal navigation                                       │
│    }                                                            │
│  });                                                            │
│                                                                 │
│  Pros: More control, doesn't affect drag-and-drop               │
│  Cons: Right-click "Open in New Tab" won't work                 │
│                                                                 │
│  RECOMMENDED: Combination approach                              │
│  - Use <a> wrapper with href                                    │
│  - Prevent default on regular click for SPA navigation          │
│  - Let modifier keys and right-click use native behavior        │
│                                                                 │
└─────────────────────────────────────────────────────────────────┘
```

#### Implementation Plan

1. Wrap kanban cards in `<a>` tags with proper `href="#/issue/{label}"`
2. Handle regular click to prevent default and use SPA navigation
3. Let Cmd/Ctrl+Click and right-click use native browser behavior
4. Ensure drag-and-drop still works (start drag on mousedown, not click)

#### Files to Modify

- `v0.1.5/components/kanban-board/kanban-board.js`
