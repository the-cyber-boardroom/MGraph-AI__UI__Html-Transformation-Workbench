### 4. CRITICAL: PATCH Properties Shallow Merge

Your backend-briefing.md asks: "Does PATCH support nested property updates?"

**Answer: Partially — with a caveat.**

The current `Node__Service.update_node()` does:
```python
if request.properties is not None:
    node.properties.update(request.properties)
```

This is a **shallow merge**. The `dict.update()` method replaces keys at the top level.

**Example of the problem:**

```javascript
// Node currently has:
properties: { 
    severity: "high",
    comments: [...existing comments...] 
}

// UI sends:
{ properties: { comments: [newComment] } }

// Result (WRONG - loses severity!):
properties: { 
    comments: [newComment]  // severity is GONE
}
```

**Workaround for UI (until backend fixes this):**

Always send the complete properties object:
```javascript
async addComment(nodeLabel, commentText) {
    const node = await this.graphService.getNode(nodeLabel);
    const properties = { ...node.properties };  // Copy ALL existing properties
    const comments = properties.comments || [];
    comments.push({
        id: crypto.randomUUID(),
        author: 'human',
        text: commentText,
        created_at: Date.now()
    });
    properties.comments = comments;
    
    // Send complete properties object
    await this.graphService.updateNode(nodeLabel, { properties });
}
```

**Backend fix coming:** We'll implement deep merge for properties.

### 5. link-types.json Format Mismatch

Your proposed format:
```json
{
  "has-feature": {
    "inverse": "feature-of",
    "description": "Version has this feature"
  }
}
```

**Actual schema format:**
```json
{
  "link_type_id": "7a8b9c0d",
  "verb": "has-feature",
  "inverse_verb": "feature-of",
  "description": "Version contains feature",
  "source_types": ["version"],
  "target_types": ["feature"]
}
```

**Action:** Use the actual schema format. The `source_types` and `target_types` arrays are important for validation.
